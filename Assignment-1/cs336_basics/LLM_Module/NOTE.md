##### 关于线性层wight为什么要定义形状为(feature_out, feature_in)，后续矩阵乘法时再转置的问题
* 在计算机内存中，无论是 CPU 还是 GPU，多维张量都是被“拉平”存储在一维的线性内存条中的。PyTorch 默认使用行优先（Row-major）的内存布局。 当定义 (out_features, in_features) 时，每一行的 in_features 个元素在物理内存中是连续的。 
* 在计算矩阵乘法时，输出的每一个神经元（对应 out_features 中的一个维度），本质上是用输入的特征向量 x 去和权重矩阵的某一行做点积。 因为这一行的数据在内存中是连续的，CPU/GPU 的缓存机制可以一次性把这整行数据高效地抓取到寄存器中完成计算。
反之：如果将权重定义为 (in_features, out_features)，在计算某个输出神经元时，需要去读取矩阵的一列。在行优先的内存中，按列读取意味着内存指针需要不断地“跳跃”，大幅拖慢计算速度。
##### 关于RMSNorm层，为什么需要将输入提升为 float32 类型再进行平方运算
* 保证数值稳定性，具体可以拆解为防止溢出和减少累加精度损失。如果在 FP16 下直接计算 x<sup>2</sup>，只要 x 的绝对值大于 256，计算结果就会直接溢出变成 inf。此外，累加数千个元素的平方值会使总和迅速变大，如果直接使用尾数精度极低的 bfloat16 或 float16 进行计算，会引发“大数吃小数”的截断现象——即累加池变大后，后续较小的值在相加时会因超出尾数表示范围而被直接舍弃，导致最终算出的 RMS 值严重偏小。
##### 为什么RoPE不会污染语义
* RoPE 不太污染语义，是因为它不是把位置当作额外向量直接加到语义上，而是对语义向量做保持范数的旋转变换，把位置信息编码为“相位”而非“内容叠加”；同时它主要作用于注意力中的 Q 和 K，服务于相对位置关系建模，因此比直接加法位置编码更少破坏原有语义结构。
