# BPE 训练算法性能优化日志

## [2026-03-28] 优化一：核心循环数据结构重构

### 1. 基准测试
* **环境/参数**: `vocab_size=10000`, 语料库 `TinyStoriesV2-GPT4-valid.txt`, cProfile 测试
* **总耗时**: 263.74 秒
* **CS336官方测试耗时**: 1.5 秒 
* **主要瓶颈**: 合并后查找被影响的序列时，`any()` 及内部生成器 (耗时 ~167s)。每次合并都需要全局扫描 `token_freq_table` 查找包含 candidate_pair 的序列，时间复杂度为 O(N)。

### 2. 修改内容
* **引入倒排索引 (Inverted Index)**：新增 `pair_to_words` 字典，记录每个 pair 所在的 token 序列。
* **架构权衡**：采用“空间换时间”策略，虽然增加了少许内存开销来维护索引集合，但成功将查找受影响序列的时间复杂度从 O(N) 降至 O(1)。

### 3. 避坑记录
* **尝试**：试图用 `max(..., key=lambda x: ...)` 单行代码替换原有的三行查找最高频 Pair 逻辑，以期减少一次字典遍历。
* **结果**：性能不升反降。
* **原因剖析**：Python 内置的单纯数值对比底层为 C 实现，速度极快；而 `lambda` 会引入昂贵的函数调用栈开销和海量临时元组的创建销毁。在 Python 环境下，轻量级的双重遍历优于沉重的单次遍历。

### 4. 优化后结果
* **总耗时**: 17.51 秒 (提速约 15 倍)
* **CS336官方测试耗时**: 0.28 秒


## [2026-03-29] 优化二：大文件流式读取/预分词内存优化

### 1. 基准测试
* **环境/参数**: `vocab_size=10000`, 语料库 `TinyStoriesV2-GPT4-train.txt`, size: 2.23G
* **总耗时**: 无限期卡顿 / 进程被系统 Kill (OOM)。
* **主要瓶颈**: 使用 f.read() 将整个 GB 级文件一次性读入内存，直接导致内存溢出或触发系统极度缓慢的 Swap (虚拟内存) 交换。 全局执行 regex.findall(PAT, text) 生成了包含整个数据集所有单词的超大列表，内存消耗增加。

### 2. 修改内容
* **引入流式读取 (Streaming)**：：废弃 f.read()，改用 for line in f: 逐行读取文件。通过生成器模式，无论文件多大，内存中始终只保留当前处理的一行文本，将空间复杂度从 O(N) 降至 O(1)。
* **正则预编译**：将复杂的正则表达式 PAT = regex.compile(...) 提取到循环外部预先编译。避免了在每次切分 chunk 时隐式调用编译所带来的 CPU 资源浪费。

### 3. 优化后结果
* **总耗时**: 1187.06 秒

## [2026-04-10] 优化三：参考官方提供的并行预分词示例代码，预分词阶段多进程并行处理

### 1. 基准测试
* **环境/参数**： vocab_size=32000, 语料库`owt_train.txt`, 特殊 token ["<|endoftext|>"]
* **总耗时**:  11637.34 秒

### 2. 修改内容
* **新增 find_chunk_boundaries 函数**：主进程首先获取文件总大小，均分逻辑块后，利用 seek 指针在边界附近预读小块 (Mini-chunk) 数据，向下寻找最近的特殊 token (<|endoftext|>) 或换行符作为绝对安全的物理切分点，防止强行切断单词或特殊标识符。
* **零数据传输策略**：在给子进程分配任务时，不通过进程池传递真实的文本数据，而是仅仅下发 (start, end) 字节偏移量坐标。
* **子进程独立读取与计算**：每个子进程拿到坐标后，各自独立打开目标文件 (rb 模式)，seek 到专属起始位置并精准读取对应大小的二进制块。随后在子进程内部独立完成解码、正则编译、文本切分和词频统计，最终只返回轻量级的局部 Counter 字典。

### 3. 避坑记录 & 架构权衡
* 如果主进程就读入文件，主进程向子进程发送字符串文本时会产生极其恐怖的 IPC (进程间通信) 序列化/反序列化开销，甚至比单线程还要慢。
* 采用下发坐标，各自读取的策略，数据零拷贝、零传输。同时为了负载均衡和防止局部 OOM，在处理超大型语料库时，可以将任务切分得更细（desired_chunks = num_workers * 24），确保每个子进程每次只处理几十 MB 的数据，不至于爆内存。

### 4. 优化后结果 (Results)
* 当前总耗时: `vocab_size=10000`, 语料库 `TinyStoriesV2-GPT4-train.txt`, size: 2.23G 耗时407.16 seconds
* 当前总耗时: `vocab_size=32000`, 语料库 `owt_train.txt`, size: 11.9G 耗时 8524.85 seconds
